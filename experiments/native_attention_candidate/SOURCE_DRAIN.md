# Prospective source-owned complete-phase drain

This opt-in candidate addresses a complete-journal intake race. The old R3
HTTP response, 262 events, 260-event authenticated status, strict rejection,
source tuple and archived bytes are retained. This contract does not reinterpret
that run as qualified. No formal traffic guard is opened.

The exact Host 5fff preimages are archived under `source/drain-199`. The
source-builder emits a new Host patch and requires a fresh source commit, genuine
wheel, installed-byte/source audit, recipe, nonce and cohort. Ascend caller/ELF
bytes are unchanged. Enable `ECPA_NATIVE_PHASE_DRAIN=1`; missing opt-in cannot
produce a closed-phase qualification. This is a dedicated single-phase protocol.

Host scheduler `has_requests()` includes `has_finished_requests()`. EngineCore
`step()` still dispatches `execute_model` for the cleanup-only batch. Ascend calls
`_update_states` before its zero-token return. The new Host hook runs after the
actual finished-request cache and InputBatch removals. It refuses an ID that is
still present, scheduled or resubmitted. Finished/aborted removal proves transport
closure, not successful task completion; strict HTTP and model oracles remain
separate. These are pinned source-order premises, not new NPU observations.

All opted-in native, tensor and OP producer callbacks synchronously authenticate
and await the real collector ACK. The worker records each ACK sequence, event
hash and raw hash. The removal hook publishes a small typed marker containing
the count, digest of the complete ordered ACK list and last actual ACK. The
collector independently rebuilds the same list from its accepted original
facts. It verifies current kernel peer/epoch, registered source bytes, actual API
mapping, full list, and prior acceptance <= source removal clock <= marker
acceptance. No owner-supplied token count, quiet interval or filtered chain is a
drain. Missing receipts or failed ACK cannot complete source closure.

`drain_collector` requires a private predeclared `--drain-policy` file binding
spec and tensor policy hashes, one exact phase and ranks 0/1. It journals all four
starts, every mapping/tensor/projection/upload/OP event and both source markers.
A closed sender submitting another fact poisons collector status and is rejected.
`describe` fsyncs the journal under the intake lock and issues `source_drain`
status with actual closed ranks and the complete stable prefix. Consumers must
wait for both registered ranks, authenticate that final status, and verify the
entire unfiltered chain. Polling completion is waiting for source evidence, not
using a quiet interval. Effect facts retain the original HTTP source-clock
window. Removal/drain controls may occur after the HTTP response, within the
predeclared enclosing phase/authentication budget.

The CPU fixture exercises real processes, Unix SO_PEERCRED, HTTP, durable raw
intake and source removal predicate with synthetic serving/NPU metadata. It is
not a genuine GPU source producer or hardware qualification. Selected logical
KV bytes/native argument completion retain their limited scope; attention
internal math and full model quality remain unknown. Formal H3/H4 remain zero.
