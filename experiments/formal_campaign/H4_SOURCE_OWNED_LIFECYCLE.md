# H4 source-owned lifecycle cost candidate

This directory mirrors proposed repository paths. It has not been copied into
or committed in the active H3 checkout. No device experiment has been run here.

The first cell remains compatible-resource-pair.lifecycle-only with the original
three arms, three Latin-square starts per arm, original short workload and cost
thresholds. The full native KV Plans and old evidence remain untouched. Generic
Manager runtime bundle/config identities describe only this independent H4
activation/cost scope; they never discharge native semantic obligations.

The runner opt-in is the preregistered arm environment
`ECPA_H4_SOURCE_OWNED_PAIR=1`, matched in all three arms. Only the runner supplies
`ECPA_H4_RUN_DIRECTORY` from the actual start directory. A source-owned receipt
must admit all new helper bytes. The old default runner and H3 protocol retain
their previous behavior.

`h4_owned_resources.py` samples the real root Popen epoch and all actual
/proc descendants across process groups and sessions every 0.25 seconds. The
same own-plus-reaped-child CPU tick and summed live RSS definitions are used.
Every ancestry edge is checked twice; a reaping race retries the sample rather
than counting the old child together with newly credited parent child ticks.
Original proc stat text and RSS lines are retained for independent replay.
Root epoch loss, source mutation or a previously owned live process escaping
ancestry prevents a complete resource-coverage claim. NPU values retain actual
registered command stdout/stderr and are independently recomputed from raw SMI
bytes. No device command was invoked during author CPU tests.

`run_h4.py` waits for the real health endpoint and a separate independently
verified loader-ready receipt within the original startup bound. It performs no
extra model POST qualification. It drives the original warmup and measured
requests, then binds resource samples and final activation receipts through the
existing hashed process snapshot. `analyze.py` calls the explicit new intake to
recompute those raw claims. Missing evidence in a failed attempt remains
unverified; it is never invented as zero or as a successful pair activation.

Author CPU tests and regression have passed. Source publication, a fresh actual
runtime/source audit and a registered H4 receipt are still required before root
executes the first real H4 start. CPU fixtures and prior two-MOD functional
qualification do not count as formal starts or cost measurements.

Published source admission additionally binds the unchanged existing runtime
source-closure and baseline-wrapper dependencies. The manifest excludes copied
unchanged fixtures, H3 helpers and schema files used only by the isolated test
overlay. No active H3 checkout files were edited for this candidate.

The source-owned cost boundary is the actual product Manager/Host Popen call
(CLOCK_MONOTONIC_RAW immediately before and after) to the runner's first real
health HTTP 200. The wrapper's common source/wheel/model qualification and its
five common phase probes remain fully executed and archived separately. They
are additional experiment qualification, not measured product phase bins. No
inclusive startup number is reduced by an estimated audit duration. The Manager
process's own discovery, validation, planning, rendering and evidence setup all
occur after its actual Popen and remain included in the startup total.

The source-owned sampler retains the full witness/descendant tree for ancestry
and cleanup replay. CPU and RSS metrics are recomputed only for the actual
product Popen kernel epoch and descendants. Fresh product CPU starts at zero,
so CPU used before the first 250 ms observation is included. Witness audit CPU
and RSS are excluded; NPU memory retains actual device readings during samples
containing the product. The default legacy measurement mode remains unchanged.

Product internal phase boundaries are not yet independently instrumented.
The six phase bins are explicitly null/unobserved, with an opt-in schema branch;
legacy numeric interval requirements remain strict. Intake binds actual product
launch timing, the independently observed health clock and sampled kernel epoch.
The aggregate retains validated starts and available headline metrics, but marks
missing product phase bins and stays incomplete. This candidate provides a
prospective measurement definition, not measured H4 values or satisfaction of
the original phase-bin requirement. Thresholds and the original workload are
unchanged.
