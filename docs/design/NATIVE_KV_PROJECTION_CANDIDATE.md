# KVCompress metadata and uploaded destination candidate

This new cohort candidate does not modify the sealed generic native-interface
qualification or register a formal producer. The formal real traffic guard
remains closed. GPU tensor content, attention consumption, and generation quality
remain unknown. All CPU socket tests mark native/GPU facts as fixtures.

The exact 00cc provider hook is after the acknowledged prior execution barrier,
request block list rewrite, Host CPU block-table row write, and active anchor
update, before the old informational ACK log. Its source-owned fact reads those
actual objects; it does not accept a caller's success Boolean or supplied row.
The pinned Host block-table blob writes block IDs without expansion. Other
logical-to-physical mappings are unsupported, rather than inferred.

Apply both source-bound patches in fresh Host/KVCompress trees and copy the three
exact source modules listed by `native_kv_source/source-binding.json` into
`vllm/plugins`. Bootstrap inventories must pin all these files plus the actual
provider, block-table, and native upload hook source bytes. Rebuild and audit new
clean wheels. Existing a4bd/00cc wheels and historical raw artifacts are unchanged.
No native NPU qualification of this candidate has been performed.

Use collector spec `ecpa-native-kv-semantic-collector-prereg/v1`, retaining every
field of generic v1 and adding `kv_requirements` indexed by the preregistered
phase ID. For the historical H2 transaction predicate the new request recipe
must preregister group 0, semantic anchor 1201, physical anchor 1024, allocation
block size 128, destination block count 8, and compression threshold 1152. The trigger threshold is 1152
(1024 budget plus 128 recompute); that scheduling trigger is a recipe/source
precondition; the receipt reads the actual runtime threshold but does not prove scheduling eligibility. Actual destination IDs
are read after effect; they are never invented or copied from the old run.
The required fields are `attention_group`, `semantic_anchor`, `physical_anchor`,
`allocation_block_size`, `destination_block_count`, and `compression_threshold_tokens`. New launch/source/nonce
bindings are required; nothing retrofits old H2 or generic native artifacts.

The existing authenticated socket accepts a third raw schema only under this
explicit opt-in spec. Kernel-authenticated worker identity, frozen source bytes,
actual API-to-runtime mapping, finite timestamps, exact fields, null quality
claims, and destination/anchor predicate precede durable raw ACK. A finite
single-projection-per-rank transaction is required for this cohort. Every fresh
upload is still archived and ACKed within its original bound, including earlier
or mismatching uploads. Rejected facts receive no accepted envelope.

Portable replay uses the same intake predicate. Only a subsequent upload from
the same process/rank/request/plan/launch with the same group's recorded CPU
destination prefix can discharge that rank's metadata-to-upload obligation.
Batch row numbers may legitimately move and are not guessed. Before-projection
uploads, other ranks/requests, or different destinations cannot discharge it.
The reported count is a finite observed projection-to-later-prefix binding, not
all-step stability, KV content equivalence, or full effectiveness. Raw retention
permits later inspection of every upload; no selected witness removes other raw
facts. Completion requires both ranks and an independently authenticated durable
ACK prefix, and otherwise stays unknown. Formal result remains false.
